# 04 — Фреймворк виральности + 7-блочный сценарий

## A. Как мы изучаем виральность (данные, а не догадки)

Мы НЕ выдумываем советы. Мы строим паттерны на собранных данных:
1. **Метрики**: для каждого ролика (твоего и вдохновителей) — views, likes, comments,
   ER (likes/views), дата, длительность, тема, формат, тип хука.
2. **Кодирование**: каждый ролик размечаем по признакам — формат (квиз/история/разбор/POV),
   тип хука (вопрос/контринтуитивный факт/предмет в кадре), тема, наличие CTA.
3. **Корреляции**: что коррелирует с высоким охватом и высоким ER по каждой соцсети отдельно.
4. **Гипотезы → проверка**: формулируем гипотезу, ты снимаешь, движок смотрит результат,
   обновляет паттерны. Это цикл обучения.

### Что уже видно из данных вдохновителей (старт):
- **kirills_finance**: охват тянут квизы («сколько знаешь?»); узкие разборы — высокий ER, низкий охват.
- **klinkovprofessor**: охват тянут конкретные инвест-идеи + «предмет в кадре»; база макро — высокий ER.
- **nomoeyesclosed**: кинонарратив-триллер + разборы скамов = экстремальный ER (до 15%) и охват до 580K.
- Общий вывод для крипто-ниши: **сильный хук в первые 1.5 сек + понятная история/пpole + польза/драма**.

(Полные выкладки — в `knowledge/inspirations/` и `data/<account>/report.md`.)

## B. 7-блочная структура сценария (твоя система «как Rick & Morty»)

Каждый сценарий пишется по 7 блокам. Это формат `ScriptwriterAgent`.

| # | Блок | Задача | Длительность (ориентир для Reels/Shorts ~30–60с) |
|---|------|--------|--------|
| 1 | **Захват (Hook)** | за 1–1.5 сек дать причину НЕ листать: вопрос/шок-факт/предмет | 0–2с |
| 2 | **Удержание (Retention)** | пообещать ценность/интригу: «сейчас покажу, почему…» | 2–6с |
| 3 | **Завлечение (Engagement)** | втянуть зрителя: вопрос к нему, ставка, «угадай до конца» | 6–12с |
| 4 | **Объяснение (Explanation)** | суть: история/разбор/пример, по шагам, просто | 12–35с |
| 5 | **Вдохновение (Inspiration)** | «что это меняет для тебя», смысл, эмоция | 35–45с |
| 6 | **Действие (Action / CTA)** | один чёткий призыв: подписка/сохранить/коммент | 45–52с |
| 7 | **Заключение (Conclusion)** | кольцевая фраза/петля назад к хуку, чтобы досмотрели/пересмотрели | 52–60с |

### Правила качества блоков
- Хук и удержание решают охват. Если они слабые — остальное не важно.
- Один ролик = одна мысль. Не пихать три темы в один.
- Язык: под аудиторию UZ — простой ру/уз, локальные примеры (Ташкент, сум, локальные реалии).
- CTA — ровно один, конкретный.
- Заключение — «петля»: возвращает к началу, повышает досматриваемость и пересмотры
  (ключевой сигнал для алгоритма).

## C. Различия по соцсетям (почему workspaces независимы)

| Параметр | Instagram Reels | TikTok | YouTube (Shorts/видео) |
|---|---|---|---|
| Длина-свит-спот | 15–45с (Reels) | 15–34с | Shorts <60с; видео 6–12 мин |
| Главный сигнал | досматриваемость + sends/saves | watch time + завершения + rewatch | watch time + CTR превью (для long) |
| Хук | визуальный + текст на экране | резкий, «паттерн-брейк» | заголовок + превью (long), хук (shorts) |
| Хэштеги | умеренно, нишевые UZ | трендовые звуки важнее | теги + описание + превью |
| Особое | sends в личку = буст | звуки/тренды/дуэты | сессии и связки роликов |

Эти правила зашиты в `workspaces/<net>.py` и используются всеми агентами.
По мере сбора данных правила уточняются (раздел A).
