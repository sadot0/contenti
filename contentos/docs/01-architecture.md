## Почему так

- **Workspaces независимы**: ты явно просил, чтобы соцсети не «смешивали логику».
  Каждая — отдельный модуль со своими правилами (длина, формат хука, структура, метрики).
  Общая только база знаний о тебе и рынке.
- **Агенты переиспользуются** всеми workspace, но получают разный контекст/конфиг от workspace.
- **LLM-бэкенд абстрагирован** → завтра меняешь Ollama на другую модель одной настройкой.
- **Knowledge base — это markdown/json в git**: прозрачно, версионируемо, читаемо человеком,
  и одновременно — контекст для агентов.
- **Ingestion отделён** (это уже готовый `contenti`): движок не зависит от того, как именно
  добыты данные.

## Поток данных (пример: новый Reel для Instagram)
1. Ты в дашборде: «хочу ролик про [тема]» (или движок сам предлагает из трендов).
2. Orchestrator берёт `workspaces/instagram` (его правила) + knowledge (твой стиль, что заходит).
3. `producer` → бриф: угол подачи, цель, целевая эмоция, длина.
4. `scriptwriter` → сценарий по 7 блокам, под твой голос, на ру/уз.
5. `packaging` → хук (первые 1.5 сек), варианты заголовка, идея обложки, хэштеги под UZ.
6. `virality_analyst` → оценка потенциала + что улучшить.
7. Результат в дашборд, ты правишь/утверждаешь.

## Технологии
- **Python 3.11+** — ядро (агенты, бэкенд, workspaces).
- **Ollama** — локальный LLM-рантайм (модель: уточнить, вероятно Qwen2.5).
- **FastAPI** — API между фронтом и ядром.
- **Next.js/React** — дашборд (этап 3).
- **faster-whisper** — транскрибация (уже используется в `contenti`).
- **yt-dlp** — скачивание YouTube (добавить локально).
- Хранение: файлы (md/json) в git на старте; БД (SQLite) — если понадобится.
