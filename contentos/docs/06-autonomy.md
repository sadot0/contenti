# 06 — Автономность: локально, с интернетом, дёшево и эффективно

Как сделать так, чтобы движок «сам включался» и работал — локально, с доступом в интернет,
малозатратно, но сильно эффективно.

## Главный принцип
«Сам включается» делает **планировщик на твоей машине**, а не облачный ассистент.
Облачный Claude (я) — для разработки и стратегии. Рантайм продукта — **локальный**.

```
[ТВОЯ МАШИНА 24/7]
  cron / systemd / Task Scheduler   ← «будильник», сам запускает движок по расписанию
        │
        ▼
  collectors (Python, ходят в интернет: RSS, instaloader, yt-dlp, web-search)
        │  обновляют
        ▼
  knowledge base (файлы) ── читает ── Ollama (Qwen2.5, локально, $0 инференс)
        │
        ▼
  agents: trend → producer → scriptwriter → packaging → virality
        │
        ▼
  готовые идеи/сценарии → дашборд + уведомление тебе (Telegram-бот)
```

## 1. Локально + автономно
- Движок = Python-скрипты ContentOS на твоём железе (ПК с GPU / мини-ПК / Mac на Apple Silicon),
  желательно включённом постоянно.
- Автономность = системный планировщик:
  - Linux/Mac: `cron` или `systemd timer`.
  - Windows: Task Scheduler.
  - Пример (cron, каждый день в 8:00): `0 8 * * * cd /path/contentos && python -m contentos daily`
- LLM: локальный **Ollama** (`ollama serve` + `ollama pull qwen2.5:7b-instruct`).

## 2. Выход в интернет
- **Ollama сам в сеть не ходит.** В интернет ходят наши модули-сборщики; модель обрабатывает текст.
- Дёшево/бесплатно:
  - **RSS** новостей (крипто + UZ-источники) через `feedparser`.
  - **instaloader** (с твоей сессией) — метрики/контент конкурентов.
  - **yt-dlp** — YouTube.
  - Опционально дешёвый/бесплатный **web-search API** (напр. Brave Search free tier).
- Сетевые модули складываются в `contentos/collectors/` (фаза 2).

## 3. Малозатратно, но эффективно
- Локальный инференс = **$0**. Затраты — электричество/железо.
- Эффективность даёт не размер модели, а:
  1. отточенные промпты и «скилы» (затачиваем итеративно);
  2. разделение задач: тяжёлое+редкое (позиционирование) — раз в месяц; частое (идеи) — на лёгкой модели;
  3. кэш знаний в файлах (не пересчитываем каждый раз);
  4. человек в петле — не тратим ресурсы на брак.
- Опциональный гибрид: 90% локально бесплатно; редкие «тяжёлые» задачи — разовый дешёвый
  облачный вызов (через сменный LLM-бэкенд). По умолчанию — всё локально.

## Реализм по железу
- Qwen 7–14B комфортно: GPU 8–12 ГБ ИЛИ Mac Apple Silicon (M1/M2/M3+).
- Голый CPU — работает, но медленно (как мы видели на whisper large-v3). Для частых задач
  бери модель полегче и/или GPU.

## Рекомендуемый минимальный сетап
1. Машина, работающая 24/7 (твой ПК/Mac/мини-ПК).
2. Ollama + Qwen2.5 (7B или 14B по железу).
3. cron/systemd/Task Scheduler — расписание.
4. `feedparser` + `instaloader` + `yt-dlp` — интернет-сбор.
5. Telegram-бот — присылает тебе готовые идеи утром (бесплатно).

## Что для этого нужно реализовать (бэклог автономности)
- [ ] `contentos/collectors/` — RSS, IG-метрики, YT, (опц.) web-search.
- [ ] `contentos daily` — команда полного цикла для cron.
- [ ] Telegram-уведомления.
- [ ] Логи/health, чтобы знать, что цикл отработал.
